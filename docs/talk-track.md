## A · 5 分钟开发岗版

### 0:00–0:40 一句话定位

"我做的是**企业智能体的运行时与评测线**。有两段经历形态相反：
一段是在成熟 LangGraph 栈上做保险理赔多智能体 + RAG（引擎驱动），
另一段是在一个⛔ 常驻进程、沙箱⛔ 让装包的平台里，把契约层、依赖调度、取数口径、
评测门禁**自己写出来**（宿主驱动）。这个项目（`agent-runtime-forge`）就是
**把同一个业务问题在两种编排范式上各实现一遍**，用数据⛔ 用偏好回答'该不该自研'。"

### 0:40–1:50 架构与四条主线

（对着 README 的架构图讲）

1. **取数层**：确定性公式 + 度量注册表，`as_of` 显式注入、金额用整数分、
   **无数据返回 None 而⛔ 返回 0**。合成数据刻意保留真实稀疏性
   （权限配置 18 条 / 750 用户、回款计划金额只有 8%），因为稀疏性才是逼出正确设计的东西。
2. **编排层**：三条线并存 —— 官方 `create_agent`（主流、带中间件）、
   手写 50 行最小 ReAct 环（"框架里面转的是什么"有代码兜底）、
   以及公司范式的**无环图 + 批次并行**。
3. **契约层**：`describe()` 全部**由代码派生**（pydantic 元数据 + AST 解析 compute +
   `inspect` 签名），合法枚举⛔ 手抄；`run(intent)` 未知键丢弃点名、越界钳位、
   非法枚举**回带合法值**让宿主自愈，且⛔ 模糊匹配。
4. **评测层**：86 条用例 → 80 格矩阵（域来自注册表，⛔ 人挑题）、逐句回归差集、
   judge 分"规则核验 + 模型判断"两段、失败归四类。

### 1:50–3:00 两个我最想讲的硬结论

**① 并行共写竞态：框架把静默覆盖变成了两种截然不同的失效。**
同一批里两路都往同一份交接文件写来源标记，实测**后写者把整份文档换掉**（连"两条都跑过"的
记录都只剩一路），而且**⛔ 任何异常**——这就是当年它能在生产活下来的原因。
LangGraph 里如果两个节点**返回同一个 channel key**，框架会直接抛
`InvalidUpdateError: Can receive only one value per step`；但**原地改共享对象**或
**共写外部文件**它⛔ 管。⇒ 所以解法⛔ 是加锁，是"**别共享**"：各分支写自己的 state 通道，
只有 fan-in 单点写，合并语义用 reducer 显式声明。
压测：同 thread 20 次 + 20 thread 并发 ⇒ **0 次覆盖**。

**② "已完成节点永不重跑"⥒ 无条件成立。**
崩在节点中间时，上一个节点会不会重跑**取决于那次 checkpoint 提交了没有**——
我用命令行测是 3/3 重跑、放进 pytest 就不重跑。⇒ 结论是**节点必须幂等、
有副作用的写必须放到人工闸后面**。这条是我自己踩出来的，⛔ 任何教程会这么写。

### 3:00–4:10 评测与数字（每个都可反查）

- RAG 质量档（`bge-small-zh-v1.5` + faiss + jieba，检索单位 = 29 条口径）：
  **top1 引用正确率 54.4% → 60.6%**（bm25 → dense，随机基线 3.4%），
  Recall@5 71.6% → 75.5%（基线 17.2%）。
  ⚠️ 我**⛔ 报 Recall@5 当头条**：语料小时它会饱和，第一版我用 6 章粒度测出 0.98，
  还得出了"hybrid 最优"的假结论——粒度改对之后结论反了（hybrid 的 top1 反而低于 dense）。
- **Reranker 是双向结果**：Recall@5 抬到全场最高 77.98%，但 top1 掉到 53.52%。
  解释是长条目下 cross-encoder 偏爱"提得多"的块。所以我报 dense 的 top1，
  并把 Reranker 说成"当前粒度下默认关，要翻盘得先把块切细"。
- 服务：SSE 两条流（节点流 / token 流），`done` 事件**自报** `stream_kind`
  是真 token 还是打桩消息块；下游全挂时返回 **200 + 合法信封 + ok=false**（⛔ 裸栈）。
- 能失败：`pytest` 191 条 + **40 项变异**（把实现改歪→对应测试必须红，改回→绿）。

### 4:10–5:00 边界：我没做什么（主动交底）

1. 受限平台那段：⛔ 环、⛔ 跨调用 checkpoint、⛔ 流式 —— 是**分工**（循环归宿主），
   而⛔ 能力缺失；这三样我在**个人项目**里真做过，所以能对比着讲代价。
2. Reranker 实测**没带来 top1 提升**，当前默认关。
3. 评测语料与 QA 集是**自建合成**，⛔ 生产问答质量；数字随依赖变（装 jieba 后 BM25 从
   0.8698→0.9806），所以每个数都带着 embedder/分词器一起印在报告里。
4. 容器编排那一档延迟**只在容器真跑通后才报**；本机单实例的 P95 是另一组数，
   两者⛔ 混着引用。

## B · 2 分钟 HR / 非技术版

"我两段实习都在做同一件事：**让企业里已有的系统能被'问'，而⛔ 被'点'**。

第一段在郑州，用成熟框架做了一个保险理赔的智能体：以前审核要人工看单据、查条款，
现在系统自己把单据读出来、对条款、给出结论，理赔全流程时效**从 2.1 天降到 0.7 天**，
自动审核覆盖率 **76%**。

第二段在常州一家做非标装备的公司，情况正相反——公司的六套老系统跟 AI 毫无关系，
平台也⛔ 提供现成的智能体框架，所以那一层是**公司自己写出来的**。
我在里面负责四块：让程序能被大模型正确调用、把多个查询安排成能并行、
把所有业务算术从模型手里拿走（**它一算数就会一本正经地答错**）、
以及给改动建一套'改一行就亮红灯'的质检。
结果是 PM 问一次项目进度，从跨几个系统手工汇总变成**一句话、33 秒**拿到。

用一句话概括我的特点：**我给大模型的不确定性建工程约束**——
数字要能反查、权限算不出来就拒答、改动一定会被测试抓住。
这两段正好是智能体落地的两条路线，**哪条的代价我都踩过**。"

## C 三个高频追问的答法（⛔ 背结论，要背**为什么**）

| 追问 | 答法 |
|---|---|
| "这不就是重造 MCP？" | 形似：`tools/list` ↔ 我的菜单自吐、`inputSchema` ↔ 我的代码派生说明书。但当时⛔ 协议层可用，只有命令行；而且 MCP **只声明 schema，⛔ 定义非法参数怎么办**——我的枚举回带、钳位说明、未知键点名都是多出来的一层。实测两者面确有差异：MCP 会把未知参数**静默忽略**，我这边点名。⛔ 说"我们实现了 MCP 协议"。 |
| "为什么不直接用 LangGraph？" | 顺序⛔ 反：① 平台只给 zip + 命令行，**没有能持循环的常驻进程**（技能是一次性 CLI、脚本还禁异步）；② 就算给，权限/口径/审计/评测/发布这几层也⛔ 在框架射程内，照样得自己写；③  LangGraph 是框架跑循环，我们是**框架出计划、模型会话跑循环**。收口："我们⛔ 在造 LangGraph 的替代品，是在造它装不进去的那个环境里的必需品。" |
| "你这评测才几百题，可信吗？" | 我自己先泼冷水：语料小 ⇒ Recall@5 饱和（瞎猜 17.2%），所以我把头条换成 top1；QA 是模板×注册表**自动枚举**生成、⛔ 我挑题（生产上我挑过，报 100%，换成矩阵后大幅回落）；所有数字连着 embedder/分词器/基线一起印在报告里，`--check` 会拦未登记的变化。 |
